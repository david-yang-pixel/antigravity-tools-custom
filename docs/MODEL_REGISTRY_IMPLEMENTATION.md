# Unified model registry implementation contract

This feature is implemented on `feat/unified-model-registry`, based on custom/main
84f3c44c. It is a single-cutover replacement, not a shadow-mode rollout. Do not
push main, deploy, or make real upstream inference calls during development.

## Invariants

- Discovery, verification, and publication are independent. Newly discovered
  models never become published automatically after the initial migration.
- A public model explicitly binds one source and one native model. Same-name
  providers do not silently steal each other's routes.
- Initial migration preserves legacy public IDs, their effective provider, and
  existing billing identity. Prices/free-model rules and balances are untouched.
- Unpublished models are denied at inference entry points, for master and user
  keys alike. Explicit administrative verification is separate from public calls.
- Registry errors fail closed; never treat a corrupt registry as permission to
  use the legacy unrestricted dispatcher.
- No claim that text verification proves reasoning, vision, or tool support.
- Generic policies belong in shared pipeline/services; provider codecs handle
  native wire differences only. Never replay Gemini thought signatures to WB.

## JSON wire contract (snake_case)

```ts
type CapabilityStatus = 'supported' | 'conditional' | 'not_integrated' | 'unsupported' | 'unverified';
interface ModelCapability {
  key: string; label: string; status: CapabilityStatus; reason: string;
}
interface ModelSource {
  id: string; provider_type: string; display_name: string;
  enabled: boolean; account_count: number;
}
interface CandidateModel {
  id: string; source_id: string; provider_type: string;
  native_model: string; display_name: string;
  account_count: number; verified_account_count: number;
  verification_status: 'unverified' | 'verified' | 'unavailable' | 'failed';
  last_verified_at: number | null; ignored: boolean;
  capabilities: ModelCapability[];
}
interface PublishedModel {
  id: string; public_id: string; display_name: string;
  source_id: string; native_model: string;
  enabled: boolean; legacy: boolean;
}
interface ModelRegistryView {
  schema_version: number; revision: number;
  sources: ModelSource[]; candidates: CandidateModel[];
  published_models: PublishedModel[]; notices: string[];
}
interface SaveModelRegistryRequest {
  revision: number; published_models: PublishedModel[];
  ignored_candidate_ids: string[];
  allow_unverified?: boolean; // default false; explicit administrator confirmation
}
interface RefreshModelCandidatesRequest { source_id?: string | null }
interface VerifyModelCandidatesRequest {
  candidate_ids: string[];
  confirm_upstream_usage: boolean;
}
interface ModelVerificationResult {
  candidate_id: string;
  status: 'verified' | 'unavailable' | 'failed';
  message: string; checked_at: number; account_id: string | null;
}
interface ModelVerificationReport {
  results: ModelVerificationResult[]; registry: ModelRegistryView;
}
```

Source IDs initially `antigravity:default` and `workbuddy:default`. Provider types
are strings at the wire boundary; the UI must not require exactly two providers.
Candidate IDs are stable, collision-free source/native pairs, generated by the
backend (do not infer by splitting the public model ID).

## Commands and routes

All administrative routes use the existing strict admin authentication.

| command | HTTP | input | output |
|---|---|---|---|
| get_model_registry | GET /api/model-registry | none | ModelRegistryView |
| save_model_registry | POST /api/model-registry | { request: SaveModelRegistryRequest } | ModelRegistryView |
| refresh_model_candidates | POST /api/model-registry/refresh | { request: RefreshModelCandidatesRequest } | ModelRegistryView |
| verify_model_candidates | POST /api/model-registry/verify | { request: VerifyModelCandidatesRequest } | ModelVerificationReport |

Mutation validates an expected revision, all IDs, source/target validity, public
name collisions, and finite collection sizes before atomically replacing data.
Revision conflicts return an explicit conflict rather than overwriting changes.
Unknown new publication requires `allow_unverified: true` after visible
confirmation; legacy models can remain enabled without fabricated evidence.
Definitively unavailable new candidates cannot be published.
Verification is selected and bounded (at most 5 candidates per action, 30 seconds
per candidate, no automatic retries that multiply usage). It must never run at
startup or during list reads. It tests basic text only and says so. Capabilities
without safe probes remain unverified or unsupported, not falsely verified.

## Rust domain module ownership/API

New `src-tauri/src/modules/model_registry.rs` provides the DTOs above and:

```rust
pub const ANTIGRAVITY_SOURCE: &str = "antigravity:default";
pub const WORKBUDDY_SOURCE: &str = "workbuddy:default";
pub fn view(legacy_ids: &[String], mapping: &HashMap<String, String>) -> Result<ModelRegistryView, String>;
pub fn save(request: SaveModelRegistryRequest, legacy_ids: &[String], mapping: &HashMap<String, String>) -> Result<ModelRegistryView, String>;
pub fn resolve_existing(public_id: &str) -> Result<Option<PublishedModel>, String>;
pub fn published_ids() -> Result<Vec<String>, String>;
pub fn record_verification(result: ModelVerificationResult) -> Result<(), String>;
pub fn candidate_id(source_id: &str, native_model: &str) -> String;
```

`view` ensures one-time initialization; later discovery only updates candidates.
The module uses account::list_accounts() / WB account metadata for discovery,
never network calls. AG quota metadata is a declaration, not successful inference
proof. WB stored per-account verified_models are text evidence only. Do not
expose credentials, emails, prompts, or tokens in DTOs.

Published IDs are compared exactly after removing a leading `models/`, not
silently lowercased or matched by arbitrary wildcard. Public IDs cannot contain
whitespace, control characters or wildcards. Preserve native ID case.

Initial migration uses the passed legacy catalog, explicit (non-wildcard) custom
mapping keys, and, if available without creating a DB, historical successful
model IDs, exact (non-wildcard) price rules and per-key free models from the
existing user_tokens.db, so every model a user key could already be billed for
stays callable. Bind WB using the old target_model
precedence, else AG using the legacy resolver. The parent provides a public
`resolve_legacy_model_route(original_model, mapping) -> String` helper in
proxy/common/model_mapping.rs, which retains the previous resolver behavior and
must not consult the registry. Migration tolerates absent historical databases,
but must not hide invalid existing WB configuration or corrupt registry data.

Store a versioned model_registry.json in get_data_dir() using existing atomic file
writes. Keep schema_version/revision, published records, ignored IDs and probe
results separate from secrets. Cache file reads/lookup, scope cache by data path
for tests, invalidate on writes and external file changes. Resolver must not
initialize an empty registry on its own. A missing registry returns an error until
`view` initializes it from the actual legacy catalog. Include focused Rust tests
for migration idempotency, source collisions, publication/ignore persistence,
revision conflicts, invalid inputs, explicit unverified confirmation and
fail-closed malformed data.

## Parent integration

Parent adds Web/Tauri routes and thin shared domain commands, enforces published
membership before billing, resolves explicit provider binding in dispatch,
handles implicit Responses/audio models and WS per-frame admission, and makes
all public lists + portal use the registry. The billing model ID remains the
client's public ID. Source-target rewrites must not leak into billing identity.
No unrelated auth/billing fixes or whole-app UI restyle in this change.

## Completed implementation and compatibility notes

- Startup performs the one-time local migration before background discovery.
  Legacy wildcard rules still resolve concrete historical IDs but are never
  treated as public model names. Later metadata reads cannot restore publication.
- Admission runs after authentication and before billing, for both master and
  user keys. JSON, Gemini URL, multipart/default models and restored Responses
  models are checked. Existing user-key WebSocket restrictions remain; master-key
  WebSocket frames are checked individually, including inherited model IDs.
- Explicit source/native bindings control dispatch. Public IDs remain the
  billing/free-rule identity. Same-name provider discoveries cannot steal routes.
- Registry errors deny public access. Administrative endpoints remain available;
  malformed files require operator repair rather than silent legacy fallback.
- One malformed input item (invalid public ID, invalid native target, or a
  `models/` alias that binds elsewhere than its bare ID) is skipped and listed in
  the registry notices; the bare ID keeps its own binding. Unreadable sources,
  invalid WorkBuddy configuration and aggregate limits still fail, because
  migrating without a source would silently and permanently drop its models.
- The production deployment helper verifies the registry and, on the first
  cutover, that every exact priced and free model is published; otherwise it
  restores the previous image (see `deploy/stellar/README.md`).
- Verification requires selected candidates and explicit upstream-usage consent.
  Antigravity probes use the normal outbound normalization and proxy selection
  with endpoint/compatibility retries disabled. HTTP endpoint errors alone are
  not conclusive model-permission evidence. WorkBuddy probes reserve real pool
  capacity and update one target only; withdrawn catalog grants do not regain
  active verification status merely because historical evidence exists.
- `/internal/warmup` now has a separate strict-admin boundary. The local scheduler
  authenticates with the configured admin password (or master key if absent).
  Request headers cannot opt out of publication admission on public endpoints.
- The model tab has Published / Candidates / Advanced sections. Publication and
  provider connection changes are awaited independently; advanced settings have
  their own save feedback. Web keeps server-side Cowork compression controls but
  hides local Desktop patch operations. Capability declarations, gateway support
  and basic-text account evidence are shown separately.
